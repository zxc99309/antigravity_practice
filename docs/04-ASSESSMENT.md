# 04｜測驗、證據、補考與晉級標準

## 評分規則（滿分 100）

| 項目 | 權重 | 通過所需證據 |
|---|---:|---|
| 獨立實作與正確性 | 35 | 能重做小題、結果對帳、必要約束/測試 |
| 原理與取捨說明 | 25 | 解釋設計選擇、替代選項、限制與業務假設 |
| 故障定位與復原 | 25 | 失敗注入、Log、最小重現、修復前後證據 |
| 文件、PR 與交付 | 15 | 可重建 README、操作步驟、可 Review 差異 |

每項打 0–5 分（見[能力矩陣](02-COMPETENCY-MATRIX.md)），加權分數 = Σ(該項等級/5 × 權重)。**通過：總分 ≥ 70，四項均 ≥ 2，且硬性 Gate 全數完成。**

## 硬性 Gate（分數高也不能豁免）

1. **安全**：Repo 無憑證、真實個資、不授權資料；資料公開程度可解釋。
2. **正確**：SQL/分析結果與獨立參考值核對，不能「畫面看起來合理」就算正確。
3. **可重現**：另一個環境依 README 能跑到相同核心結果（容許依 OS 的合法替代）。
4. **證據**：不能把 `NotRun` 寫成 `Passed`；記錄環境、命令與必要的輸出。
5. **本人答辯**：現場更改一個小條件，能獨立修正程式／SQL／BI 計算。
6. **關鍵階段 Gate**：P02 要證明 JOIN/Window 正確；P03–P04 要證明增量/重跑/回補正確；P07–P10 要證明業務口徑、限制與分析適切性。

## 三類驗收

- **功能測試**：是否符合明確的 Acceptance Criteria（AC）。
- **反例/故障測試**：錯誤輸入、重複資料、延遲、NULL、部分失敗、不同分母與日期邊界。
- **口頭追問**：導師選一段非預告修改，要求不依賴 AI 演示並解釋。

## 判定與重修

- `Pass`：Gate 全過、≥70、證據齊全；可進下一 Phase。
- `Needs Work`：功能可運行但某條 AC 或證據不足；列出最少重修任務並限縮下一步。
- `Blocked`：環境或資源限制；提出同等學習目標的本地替代實驗，不能假裝已部署。
- `Fail`：結果錯誤、無法解釋、抄答案或有安全風險；退回相應週次重做。

## 證據檔應記錄

- Git branch、Commit SHA、PR/Issue、改動範圍。
- OS、Python/SQL/工具版本；真實執行命令與執行時間。
- 具體輸入（可用合成資料與 seed）、預期輸出、實際輸出、差異原因。
- Unit/Integration/Data Quality/BI Reconciliation 結果；未執行的原因。
- 已知限制、改進事項、學習者自己的推理與反思。

每階段填寫 [Phase 提交模板](templates/PHASE-SUBMISSION.md)；不得由 AI 代填未發生的證據。
