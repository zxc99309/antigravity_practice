# P12｜完整零售資料平台、事故演練、移交與求職展示

> 週次 W45–W48｜學習主線：工程 × 分析 × BI｜必修 Phase。

## 目的與入口條件

**學習成果**：獨立完成一項可追溯、可回補、可分析、可分享與維護的企業型資料專案，並能應對臨時需求變更。

**前置條件**：P01–P11 的硬性 Gate 已完成（P11 可有明確限定的替代方案）。

## 需要理解的原理

- 實務需求訪談、優先級與 Scope、Architecture Decision Record
- 來源/資料契約、ETL/ELT、DB/Mart、排程、品質與監控
- 統計/商業分析、BI、權限、刷新、決策報告
- 故障演練、Incident、交接、Demo、求職 Portfolio 與技術答辯

## 每週教學與工作單

### W45｜需求與設計

**原理與研究**：與導師模擬業務訪談，設計顧客、訂單、付款、退款資料。

**本人實作**：寫 1–2 頁 PRD、KPI Dictionary、Data Contract、系統圖、ADR、AC。

**應交證據**：Reviewer 確認 Scope/設計、拒絕超出範圍的功能

### W46｜整合交付

**原理與研究**：在乾淨環境建來源、Raw/Staging/Mart、incremental、quality、workflow。

**本人實作**：保留全部輸出與版本，加入 CI；建最小 viable BI/EDA。

**應交證據**：端到端 Demo、系統 Log、可重建步驟

### W47｜故障與業務核對

**原理與研究**：導師植入三種未知故障（重複、晚到、schema/refresh）。

**本人實作**：實際排查、回補、Reconciliation，再完成 BI/統計報告。

**應交證據**：Incident Timeline + Before/After 數據與分析限制

### W48｜交接與面試

**原理與研究**：模擬新同事在乾淨機器重建、重新整理數據、提業務問題。

**本人實作**：30 分鐘展示 + 30 分鐘 Review；提交 Portfolio、運維、成本與演進計畫。

**應交證據**：最終驗收表、公開展示用脫敏素材、技術問答

## 階段專題

完成 [CAPSTONE-001](../work-orders/CAPSTONE-001-RETAIL-PLATFORM.md)：「每天早上提供昨日訂單、退款、淨收款與顧客留存；有遲到資料與管線失敗時可補齊並對帳」。

## Acceptance Criteria（逐條勾核）

- [ ] 全套由乾淨環境重建，運行時不依賴手動點選 Streamlit 上傳。
- [ ] 兩種來源、原始快照、增量、Key/粒度、資料品質與 Quarantine 完整。
- [ ] 測試同日重跑三次、兩天晚到資料、schema 變更與來源中斷。
- [ ] 具備 10 個以上明確 KPI、至少 3 個 SQL↔BI 核對、可重現 EDA。
- [ ] 可查詢 Run/Incident log、手動指定日期回補並重新刷新下游。
- [ ] Git PR、README、Data Dictionary、ADR、Runbook、Security/Cost、分析限制完整。
- [ ] 本人能離開 AI 做一題陌生 SQL、修改一個規則並回答一個事故追問。

## 必須執行的故障/反例測試

- 業務突然把「營收」改為只計付款完成且排除退款，要求說明影響與回算。
- 來源晚到兩天，報表昨日已發布，要求調整刷新與更正機制。
- 部署後沒有環境變數，要求在不印出秘密下定位錯誤。

## 常見誤區與邊界

不得只用 Demo 成功作為畢業；一定要包含故障、數據對帳、限制、可重現及本人答辯。
